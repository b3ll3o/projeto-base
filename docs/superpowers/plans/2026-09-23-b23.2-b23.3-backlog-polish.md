## Task 2 (B23.3): Corrigir 3 testes pré-existentes em stack-code-reviewer.spec.ts

**Files:**

### Diagnóstico (j́a feito pelo controller — preservar no report)

**Causa raiz:** `tooling/scripts/stack-code-reviewer.ts:52-54`:

```ts
function isDomainFile(file: string): boolean {
  return /(^|[\\/])domain([\\/]|$)/.test(file);
}
```

Função requer `/domain/` (como componente de diretório) no path do arquivo.

Os 3 testes em `stack-code-reviewer.spec.ts` criam arquivos via helper `tmpFile(name, content)` que produz paths como:
- `/tmp/stack-review-test/user.spec.ts` (test 1: `detecta blocker em domain com import proibido`)
- `/tmp/stack-review-test/domain-import.ts` (test 6: `report não aprova quando há blocker`)
- `/tmp/stack-review-test/d1.ts` + `/tmp/stack-review-test/d2.ts` (test 8: `detecta múltiplos blockers de uma vez`)

Nenhum desses paths contém `/domain/` → `isDomainFile()` retorna `false` → `checkDomain()` retorna `[]` → 0 blockers detectados → testes falham.

**Fix:** alterar `name` em cada teste para incluir prefixo `domain/` (ex: `'domain/user.spec.ts'`). `tmpFile()` já suporta subdirs via `join(dir, name)`.
